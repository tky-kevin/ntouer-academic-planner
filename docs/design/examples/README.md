# 規則包樣本

這兩份樣本用來驗證[規則描述模型](../rule-model.md)的表達力：**不是正式規則、不是已發布版本**，`status` 一律為 `draft`。

| 檔案 | 系所／年度 | 結構特徵 | 用途 |
| --- | --- | --- | --- |
| [113-cse.json](113-cse.json) | 資工 113 | 28／50／57；核心 12⊆系內 46；6 組採計上限；4 個非學分條件；電子商務衝突 | 主樣本，對應[覆蓋清單](../../../data/rules/113-cse-coverage-list.md)的 46 條 |
| [115-mmd.json](115-mmd.json) | 商船 115 | 28／70／38；必修合計 98；管理級 18⊆主領域 38；外系 8；主領域 36／38 版本衝突 | 驗證不同結構不需改引擎 |

## 已知的取捨

1. **課程鍵用課名**：113 資工的官方課號尚未對應完成，樣本以課名（如 `"程式設計"`）當 `courseCode`。正式版必須換成課號，否則同名不同課會誤判。
2. **商船以 115 為例**：113 的頁面版本未取得；115 的結構與 113 相同量級，足以驗證格式。樣本內 `pending` 的條文卡標明待系所確認。
3. **數字來源**：所有門檻都對應 `clauses[].text`，沒有來源的數字不進樣本。

## 第三個系所的驗證方式

機械與機電工程學系的「體育計入以 1 學分為限」「通識選修以 2 學分為限」（100 學年度必修科目表）只取得條文摘要、未取得完整必修表，因此**不建立樣本包**，改以[表達性矩陣](../rule-model.md#8-多系所驗證矩陣)記錄其對應的 `caps`／`perCourseCreditsMax` 寫法。沒有完整資料就不建樣本，避免假造門檻。

## 驗證

```bash
node docs/design/spike/run-cases.mjs
```

兩份樣本都會先通過 `validateBundle` 的結構檢查，再進入 27 項案例。
